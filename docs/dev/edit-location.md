# 編集位置の連携(ビューアからエディタへ)

ビューアで見ている場所を、**正確に**、エディタ(Emacs)の編集位置として渡す仕組み。ソケットの契約全体は [integration-protocol.md](integration-protocol.md)。検討の経緯と方式の比較は [poc-integration-results.md](../history/poc-integration-results.md) §5。

## 1. 目的

文書の記載ミスをビューアで見つけ、エディタで直すとき、**別の場所を直してしまう**ことを防ぐ。同じ文言が複数ある巨大な文書では、「見ていた位置」と、エディタの検索で着いた位置が食い違いうる。このため、単に近くまで連れていくのではなく、位置の正しさをエディタ側で**照合してから**移動する。

## 2. 要件

| #   | 要件                               | 意味                                                                                                                                     |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **正確な位置を指す。**             | 文言の検索に頼らず、ビューアが元の Markdown 上の位置(行・桁、または範囲)を特定して渡す                                                   |
| R2  | **食い違いを黙って通さない。**     | 位置とあわせて「その位置にあるはずの文字列」を渡し、エディタ側で照合する。一致しなければ警告し、勝手に飛ばない                           |
| R3  | **古い表示を検出する。**           | ビューアが描画した時点のファイルの識別情報(内容のハッシュ、更新日時とサイズ)を渡す。エディタ側のファイルが変わっていれば、警告する       |
| R4  | **着いた場所を、目で確認できる。** | エディタ側で、対象の範囲を一時的に強調し、「ビューアが指していた文字列」をメッセージに表示する                                           |
| R5  | **曖昧さを隠さない。**             | 位置を一意に決められないとき(選択がなく、ブロック内に同じ文字列が複数あるなど)は、確実な範囲(ブロック全体)だけを渡し、「曖昧」と明示する |

## 3. 全体の流れ

方式は「**エディタが取りに来る**」。アプリは、指した位置を記録して待つだけで、エディタに値を押し付けない。

1. 利用者が、ビューアで、文字列を選択して(または、右クリックだけ、または何も選ばず)、右クリックメニューの **`Edit in <editorName>`**(キー `C-c e`、`M-x edit-in-editor`)を選ぶ。`editorName` は設定(既定 `Emacs`)。コマンドが設定されていなければ、項目は `Record Location for Editor` になる。
2. Web コアが、**指した場所を、元の Markdown の位置にする**(§4)。
3. アプリが、絶対パスと、**ビューアが描画した版のファイルの識別情報**(SHA-256・更新日時・サイズ)を足して、記録する。設定された固定のコマンドがあれば、実行する(§7)。
4. エディタが、ソケットの `get-location` で取りに来て、**照合してから**、移動する(§6)。

仮想 buffer(検索結果など)は、編集の対象にならない(エディタで開けるファイルがない)。指した位置は、変わらない。ビューアが読んでいないファイル、警告パスで記憶されていないファイルの位置は、エディタに渡さない。

## 4. 指した場所 → 元の位置(R1・R5)

- 描画のとき、ブロック要素(段落・見出し・リスト項目・コード・表・引用など)に、元の Markdown の開始・終了のオフセットと行を残す(`data-source-start`・`data-source-end`・`data-source-line`・`data-source-end-line`)。
- 選択した文字列が、**そのブロックの元の文章の中で、ちょうど 1 か所**に見つかるときだけ、**`exact`**(その範囲)にする。
- 次のいずれかなら、**`block`**(ブロック全体、またがるときは、その全体)にして、曖昧であることを、画面にも出す。**推測で、位置を決めない。**
  - 見つからない(強調・リンク・エスケープで、見えている文字列が、元と違う)。
  - 複数ある。
  - 選択がない(右クリックだけ・画面の上端のブロック)。
  - 複数のブロックにまたがる。
- 桁は、**Unicode のコードポイント**で数える(Emacs の文字の数と同じ。絵文字などの UTF-16 の違いに影響されない)。改行は、CRLF・CR・LF のどれでも、行を数える。`expect` と文脈は、改行を LF にそろえる。
- `expect` は、先頭 500 コードポイントまで(`expectTruncated`)。前後の文脈は、40 文字ほど(行をまたいでよい)。
- **ファイルの識別情報は、ビューアに渡したバイト列**から求める(文字列にする前なので、不正な UTF-8 を含むファイルも、ディスクと一致する)。ファイルが変わって、ビューアが読み直したあとも、すでに指した位置の識別情報は、古いまま(= 古い表示に基づく位置だと、エディタが分かる)。
- 実装は、Web コア側が `core/src/locate.ts`、アプリ側が `app/macos/Sources/HyperBufKit` の `FileFingerprint`・`LocationBuilder`。

## 5. 位置のペイロード

ソケットの `get-location` の `result.location`。**定義の正本は [`protocol/schema/location.schema.json`](../../protocol/schema/location.schema.json)**、代表例は `protocol/examples/location*.json`。

| フィールド  | 内容                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ |
| `v`         | 契約のバージョン(1)                                                                        |
| `path`      | 編集するファイルの絶対パス                                                                 |
| `range`     | `start` / `end`(それぞれ `line` と `column`。1 始まり。桁はコードポイント)                 |
| `precision` | `exact` または `block`(§4)                                                                 |
| `expect`    | その範囲にあるはずの、元の Markdown の文字列。長いときは先頭だけ(`expectTruncated`)        |
| `context`   | 範囲の直前・直後の文字列(`before` / `after`)                                               |
| `file`      | ビューアが描画した版の識別情報(`sha256`、`mtime`、`size`)                                  |
| `viewer`    | ビューアの状態(`selection`: 選択していた、表示されているままの文字列、`version`、`readAt`) |
| `markedAt`  | 「エディタで編集」を選んだ時刻(エポックからのミリ秒)                                       |

- 内容に文書の一部(`expect`、`context`)を含むため、問い合わせの応答には接続元の確認(同一ユーザー)を必須とする([integration-protocol.md](integration-protocol.md) §3.6)。
- `get-location` は、まだ位置が記録されていなければ `null` を返す。複数のフレームがあるとき、**位置を記録したフレーム**のものを返す。
- 古い PoC の `get-location`(いまの表示を返していた)は、`get-view` に分けた。`get-location` は、利用者が指した位置だけを返す。

## 6. エディタ側の照合(R2〜R4)

Emacs の `hyperbuf-visit-location`(`emacs/hyperbuf.el`)は、移動の前に、次を、この順に照合する。**失敗したら、移動も、続行もしない**(根本的に何かがおかしいことに、本人が気づいていないことが多いので、冷静に状況を判断する機会を与える)。

1. **`stale`:** ディスク上のファイルの SHA-256 が、`file.sha256`(ビューアが描画した版)と違う。
2. **`mismatch`:** 位置が、文書の範囲外 / その位置の文字列が `expect` と違う(切り詰められているときは、先頭だけ) / 前後の文脈が違う。**未保存の編集で、位置がずれているときも、ここで検出する**(バッファの内容を、照合する)。
3. 失敗のとき: 警告(`user-error`)と、食い違いの詳細(`*hyperbuf-mismatch*`: ビューアが指していた文字列、いまの文字列、SHA-256 の違い、対処)を出す。
4. 成功のとき: 範囲を一時的に強調し、ビューアが指していた文字列を表示する。`block` のときは、「位置が曖昧なため、ブロック全体を示しています」と出す。指した位置が 10 分(`hyperbuf-location-max-age`)より古いときは、その旨を添える。

照合の規則は、`protocol/examples/location-check.json` で共有し、Emacs の適合テストで検証する。

UTF-8 以外の文字コードのファイル(Shift-JIS など)は、ビューアが UTF-8 として読むため、`expect` が合わず、`mismatch` になる(警告で止まる。誤った場所へは、移動しない)。

## 7. エディタの呼び出し(外部コマンドの実行の権限設計)

アプリは、設定された**固定のコマンド**だけを実行して、エディタに取りに来させる。設定は `config.json` の `editorName` と `editorCommand`([configuration.md](../user/configuration.md))。

```json
{
  "editorName": "Emacs",
  "editorCommand": [
    "/opt/homebrew/bin/emacsclient",
    "-n",
    "-e",
    "(hyperbuf-edit-here)"
  ]
}
```

- コマンドは、**利用者が書いた固定のもの**だけ。**文書の内容・選択・パス・位置は、引数にも環境にも一切含めない**(位置は、エディタが `get-location` で取りに来る)。注入の余地がない。
- **シェルを介さず**、引数の配列で実行する。先頭は、実在する**実行可能な絶対パス**(`PATH` の検索を許さない)。引数は 16 個まで、各 1024 文字まで、NUL を含まない。満たさなければ、設定を無視する(エディタを呼び出さない)。
- 標準入出力は使わない。期限(5 秒)を過ぎたら、終了させる。
- 設定がなければ、エディタは呼び出さず、位置を記録するだけ(エディタ側で `M-x hyperbuf-visit-location`)。

## 8. 未検証・未決事項

- 位置の指定の、キーボードだけの操作(選択のためのマーク)。`C-c e` は、選択がなければ、画面の上端のブロックを指す。
- 強調・リンクをまたぐ選択を、`exact` にすること(今は `block`)。実際の文書での、`block` になる頻度の確認。
- 署名・公証したアプリから、外部コマンドを実行できること(Hardened Runtime でも、子プロセスの実行は、制限されない想定だが、未確認)。
- Emacs 以外のエディタのために、ペイロードの形式を公開契約にするか。今は、`protocol/schema/location.schema.json` が定義するが、Emacs 以外での利用は想定していない。
