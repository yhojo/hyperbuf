# 設定(config.json)

利用者が書く設定は、1 つのファイルにまとめる。

```
~/Library/Application Support/HyperBuf/config.json
```

- なければ、標準のまま。アプリの起動時に読む(変えたら、アプリを再起動する)。
- JSON。**不正な項目は、無視して、理由を知らせる**(起動時のメッセージと、`C-h b` の一覧)。
- 設定は、利用者が自分で書くもの。アプリは、設定ファイルを書き換えない。
- アプリメニューの `Show Config File in Finder` で、`config.json`(なければ、置き場所のフォルダ)を Finder に表示する。

## 全体の例

```json
{
  "editorName": "Emacs",
  "editorCommand": [
    "/opt/homebrew/bin/emacsclient",
    "-n",
    "-e",
    "(hyperbuf-edit-here)"
  ],
  "restoreSession": true,
  "mathUnescapeUnderscore": true,
  "followUpdates": false,
  "appearance": "system",
  "alpha": [100, 100],
  "trustedUrls": ["https://github.com/yhojo/*", "https://*.wikipedia.org/*"],
  "warnPaths": ["/usr", "/opt", "/tmp", "~/.ssh"],
  "allowPaths": ["~/work", "/usr/share/doc"],
  "projectIgnorePaths": ["~/work/wrapper"],
  "keybindings": {
    "M-p": "back",
    "M-n": "forward",
    "C-x 2": "split-below",
    "C-f": null
  }
}
```

## セッションの復元(`restoreSession`)

| キー             | 型     | 意味                                                                      |
| ---------------- | ------ | ------------------------------------------------------------------------- |
| `restoreSession` | 真偽値 | 前回の状態を復元し、保存するか。**既定は `true`**(`false` のときだけ無効) |

- 復元の範囲・保存先・壊れたデータの扱いは、[session-restore.md](session-restore.md)(複数フレームは [project-model.md](project-model.md) §10)。
- `false` のあいだは、復元もしないし、保存もしない(それまでの保存は、そのまま残る)。

## 文書の表示(`mathUnescapeUnderscore`・`followUpdates`)

| キー                     | 型     | 意味                                                                                           |
| ------------------------ | ------ | ---------------------------------------------------------------------------------------------- |
| `mathUnescapeUnderscore` | 真偽値 | 数式の中の `\_` を `_` に戻して描画するか。**既定は `true`**                                   |
| `followUpdates`          | 真偽値 | 外部でファイルが更新されたとき、最初に変わった場所へ移るか。**既定は `false`**(閲覧位置を保つ) |

- `mathUnescapeUnderscore`: Marked 2 などは、Markdown のバックスラッシュのエスケープを外してから数式を描画するので、`$x\_1$` は添字の `x_1` になります。TeX では `\_` は「文字としての下線」ですが、この互換があると、Markdown の都合で `_` を `\_` と書いた数式が、そのまま読めます。`\text{…}`・`\mathrm{…}` などの引数の中の `\_` は、文字の下線のまま残します。`false` にすると、TeX の規則どおりにします。
- `followUpdates`: `C-x x u`(`toggle-follow-updates`)で、その場で切り替えられます(切り替えは、アプリの終了まで。設定は変わりません)。オンのあいだ、モードラインに `[Follow]` と出ます。移った先は、一瞬、強調されます。

## 外観(`appearance`)

| キー         | 型     | 意味                                                                                                                       |
| ------------ | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| `appearance` | 文字列 | `"system"`(OS の設定に従う。**既定**)、`"light"`、`"dark"`。`light` / `dark` は、OS の設定に関係なく、アプリだけを固定する |

- ウィンドウ・メニュー・スクロールバー・文書の表示のすべてが、これに従う。アプリの起動時に読む(変えたら、アプリを再起動する)。
- `system` のとき、アプリの動作中に OS の外観が切り替わっても、追従する。文書・コード・数式・画面の部品は、そのまま切り替わり、図(Mermaid)は、新しい外観で描き直す(閲覧位置は保つ)。
- 配色は、GitHub に近いもの 1 組(ライトとダーク)だけで、利用者が色を定義する仕組み(テーマ)は、ない。
- **画像(PNG・SVG)の色は、変えない。** 透明な背景に、暗い線や文字だけで描かれた図は、ダークでは見えにくいことがある(GitHub のダーク表示と同じ限界)。

## フレームの透明度(`alpha`)

| キー    | 型              | 意味                                                                                                                                    |
| ------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `alpha` | 整数 2 つの配列 | `[前面, それ以外]`。パーセント(10〜100。**既定は `[100, 100]`**、透過なし)。Emacs の `(set-frame-parameter nil 'alpha '(80 65))` と同じ |

- 例: `"alpha": [80, 65]` は、前面のフレームを 80%、背面のフレーム(アプリが背面のときの、すべてのフレームを含む)を 65% の不透明度にする。
- **ウィンドウ全体**の透明度で、文字や画像も、同じだけ透ける(背景だけを透かす方式は、ない)。
- 全フレームに、同じ値を適用する。アプリの起動時に読む(変えたら、アプリを再起動する)。
- アクセシビリティの「透明度を下げる」がオンのあいだは、設定に関係なく、不透明にする。
- 範囲外の値・形の違う値は、無視して(不透明のまま)、`C-h b` の「設定の問題」に出す。

## 外部リンク(`trustedUrls`)

文書の中の `http` / `https` のリンクを選ぶと(クリック、`RET`)、既定のブラウザで開きます。**毎回、確認します**(`yes` / `no` / `always`)。

| キー          | 型           | 意味                                                                                    |
| ------------- | ------------ | --------------------------------------------------------------------------------------- |
| `trustedUrls` | 文字列の配列 | 確認なしで開く URL のパターン。`*` は任意の文字列。`http://` または `https://` で始める |

- `always` と答えたサイト(`scheme://host[:port]`)は、`~/Library/Application Support/HyperBuf/trusted-sites.json` に記憶します。`M-x forget-remembered-site` で取り消せます。
- `mailto:` は、毎回、確認します(`always` はありません)。それ以外のスキーム(`file:`・`javascript:` など)は、開きません。
- ユーザー名・パスワードを含む URL(`https://example.com@evil.example/`)、制御文字を含む URL、2048 文字を超える URL は、確認もせず、開きません。
- ブラウザを開く判断は、アプリ(Swift)が、もう一度、確かめます(Web 側の判断は信用しません)。

## プロジェクト・ルート(`projectIgnorePaths`)

`C-x p f` / `C-x p g` / `C-x p b` / `C-x p k` は、いま見ているバッファのディレクトリから親へさかのぼり、最初に VCS の目印(`.git`・`.hg`・`.svn`・`.bzr`・`_darcs`・`.jj`)があるディレクトリを、プロジェクト・ルートにします。見つからなければ、バッファのディレクトリ(`default-directory`)自身です。`~` と `/` は、ルートにしません。フレームとの対応はなく、バッファごとに決まります(詳細: [project-model.md](project-model.md) §14)。

| キー                 | 型           | 意味                                                                                   |
| -------------------- | ------------ | -------------------------------------------------------------------------------------- |
| `projectIgnorePaths` | 文字列の配列 | ルートにしないディレクトリ。目印があっても飛ばして、さらに上をさがす。完全一致(下のディレクトリには効かない) |

- 絶対パス、または `~/…` で書く。相対パス、型の違うものは無視して、理由を `C-h b` の「設定の問題」に出す。
- 一覧と検索は、隠しファイルと `node_modules` を除きます。`.gitignore` は読みません。

## エディタの連携(`editorName`・`editorCommand`)

右クリックメニューの `Edit in <editorName>`(または `C-c e`)で、指した場所を記録し、`editorCommand` を実行する。

| キー            | 型                  | 意味                                                                                         |
| --------------- | ------------------- | -------------------------------------------------------------------------------------------- |
| `editorName`    | 文字列(40 文字まで) | メニューに出す名前。既定は `Emacs`                                                           |
| `editorCommand` | 文字列の配列        | 実行するコマンド。**先頭は、実在する実行可能な絶対パス**。引数は 16 個まで、各 1024 文字まで |

- コマンドは、**ここに書いた固定のもの**だけを、シェルを介さずに実行する。**文書の内容・選択・パス・位置は、引数にも環境にも含めない**(エディタが、`get-location` で取りに来る)。
- `editorCommand` がなければ、エディタは呼び出さず、位置を記録するだけ(メニューは `Record Location for Editor`。エディタで `M-x hyperbuf-visit-location`)。
- 不正なコマンド(相対パス、存在しない、実行できない、配列でない、など)は、無視する(エディタは、呼び出さない)。

詳細: [integration-protocol.md](integration-protocol.md) §15、Emacs 側は [`emacs/README.md`](../emacs/README.md)。

## ファイルのアクセス(`warnPaths`・`allowPaths`)

ファイルを開く範囲は、プロジェクトではなく、**警告パス**と**許可パス**で決める(判定の規則: [project-model.md](project-model.md) §5)。

| キー         | 型           | 意味                                                                                                                                      |
| ------------ | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `warnPaths`  | 文字列の配列 | 警告パス。この下のファイルをリンクや外部連携から開くときは、ミニバッファで確認する。**書いたら、既定の一覧を置き換える**。`[]` で警告なし |
| `allowPaths` | 文字列の配列 | 許可パス。警告パスの下で、確認を省く場所。**書いたら、既定の一覧を置き換える**                                                            |

- 既定の警告パス: `/usr`、`/opt`、`/tmp`、`/var`、`/etc`、`/System`、`/Library`、`~/.ssh`、`~/.aws`、`~/.gnupg`、`~/Library`。既定の許可パス: `~/Library/Mobile Documents`(iCloud Drive)。
- 絶対パス、または `~/…` で書く。シンボリックリンクは解決して照合する(`/tmp` は `/private/tmp` として扱う)。相対パス、型の違うもの、空のものは無視して、理由を `C-h b` の「設定の問題」に出す。
- **一番長く一致したものが勝つ**(より具体的な指定が優先)。許可と警告が同じパスなら、警告として扱い、設定の問題として報告する。
- **自分で打った・選んだパス(`C-x C-f`、`C-x p f`)は、判定しない。** 判定の対象は、リンクのクリック、外部連携(CLI・Emacs・URL スキーム)、文書が参照する画像。
- 警告パスのファイルを承認すると、そのファイルのディレクトリ以下が記憶される(`~/Library/Application Support/HyperBuf/trusted-roots.json`)。記憶は `M-x forget-remembered-path` で取り消せる。

## キー割り当て(`keybindings`)

標準の割り当て([keybindings.md](keybindings.md))に、重ねる。

```json
"keybindings": { "<キー列>": "<コマンド名>" | null, ... }
```

| 値                 | 意味                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| コマンド名(文字列) | そのキー列に、コマンドを割り当てる。同じキー列の、標準の割り当ては、置き換わる |
| `null`             | そのキー列の、標準の割り当てを外す                                             |

- **コマンド名**は、`M-x` の候補と同じ。一覧と説明は、[keybindings.md](keybindings.md)(または、アプリで `C-h b`)。
- **キー列の書き方:** スペースで区切って、最大 4 つ。1 つのキーは、修飾キーを `C-` `M-` `s-` `S-` の**順**に並べて、本体(1 文字、または `RET` `ESC` `TAB` `SPC` `DEL` `up` `down` `left` `right`)。例: `C-x 2`、`M-x`、`s-[`、`S-TAB`、`C-M-s`。
- **処理の順序は、書いた順に依存しない:** 解除(`null`)が先で、割り当ては、キー列の順。
- **無視される設定(理由は、`C-h b` の「設定の問題」に出る):**
  - 不明なコマンド名。
  - 不正なキー表記(`Ctrl-x`、`M-C-x` など)。
  - 割り当てのないキー列の解除。
  - **`C-g`**: 取り消しに予約されている(変えられない)。
  - プレフィックスとの衝突: 同じキー列を、コマンドと、プレフィックス(`C-x` の `2` など、下に続くキーがある)の両方にはできない。`C-x` を、コマンドにしたいときは、先に、`C-x` で始まる割り当てをすべて `null` で外す。
- 入力欄(ミニバッファ)の中のキーは、この設定の対象外(確定・取消・候補の選択・履歴は、固定)。

## 開発用の差し替え(デバッグビルドのみ)

テストが、利用者の実際の設定を使わないよう、デバッグビルドは、環境変数で、場所を差し替えられる(`CLAUDE.md` 参照)。

| 環境変数                 | 差し替えるもの                                        |
| ------------------------ | ----------------------------------------------------- |
| `HYPERBUF_CONFIG`        | この設定ファイル                                      |
| `HYPERBUF_SOCKET_PATH`   | ソケット                                              |
| `HYPERBUF_TRUSTED_ROOTS` | 信頼するルートの保存先                                |
| `HYPERBUF_SESSION_DIR`   | セッションの保存先(`session.json` を置くディレクトリ) |
