# 配布の準備の経緯(M8)

配布物の仕様は [distribution.md](../dev/distribution.md)、手順は [release.md](../dev/release.md)。ここには、そこに至るまでの判断と調査の記録を残す。移行計画での位置づけは [migration-plan.md](migration-plan.md)(M8)。

## 1. 最初のリリースのビルドは arm64 だけだった(2026-10-11)

最初のリリースのビルドは arm64 だけで、Intel の Mac(macOS 15.8.1)で「このOSに対応していない」と表示された。Universal(arm64 + x86_64)に直した(`swift build --arch arm64 --arch x86_64`)。

最低の macOS は 14 とした(macOS 13 は対象外)。判断の経緯は [migration-plan.md](migration-plan.md)。Intel の Mac のうち、macOS 14 に更新できないもの(2017 年の MacBook Pro など)は対象外となる。この件を受けて、配布の前に、Intel の Mac で起動を確認する手順を加えた。

## 2. 署名の確認(2026-10-10)

ad-hoc 署名の Hardened Runtime で、画面の表示、ソケット、CLI が動くことを確認した。エンタイトルメントを付けない設計(WebKit のレンダリングは Apple の WebContent プロセスが行う。外部コマンドの実行、ソケット、ファイルの読み取りは Hardened Runtime でも制限されない)の根拠である。

## 3. 同梱物の検査(2026-10-10)

`strings` で、実行ファイルと同梱物に、個人のパスや秘密情報が残っていないかを調べた。

- 実行ファイルに、ビルドしたマシンのソースの絶対パス(`/Users/…`)が残っていた。release ビルドで、`-file-prefix-map` により `/hyperbuf` に置き換えるようにした(`make-app.sh`)。置き換え後は、残っていない。
- Web のバンドルとリソースに、個人のパス・秘密情報・ソースマップはない。Bundle ID(`com.yhojo.hyperbuf`)は、意図した公開の識別子。

## 4. 既定のアイコンの決定(2026-10-12)

既定のアイコンは「H」(暗い板の上に、半透明のタイルで「H」を描いたデザイン。Yasuo Hojo の作)に決めた。知り合いへの見せ合いで、「目立つ」「H が分かりやすい」という評価を得た。

代替のデザイン(分割した 2 つの window)は、視認性の評価が分かれたため、既定にしなかった。コードから生成できる形で、`app/macos/Resources/alternatives/` に残している。

元の画像は、暗い角丸の板が画像いっぱいに広がっていて、透明な余白がなかった。macOS のアイコンは、透明な余白がないと、Dock や Finder で他のアプリより大きく、角に四角い地が見える。そこで、元の画像から、角の外側は透明、周囲に約 10% の余白、影つきの、標準のアイコンを作る変換(`icon-from-image.swift`)を加えた。

## 5. v0.1.0 と v0.1.1

- **v0.1.0(2026-10-12):** 関係者への非公開の配布を開始した。Intel の Mac mini(macOS 15.8.1)で、起動と使用を確認した。初回のフィードバック 8 件に対応した。
- **v0.1.1(2026-10-14):** フィードバックへの対応をまとめた版。配布の `.dmg` に `CHANGELOG.md` を同梱し、利用者が更新内容を確認できるようにした。
