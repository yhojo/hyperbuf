# セッションの復元

アプリを終了して起動し直したあとに、作業中の状態を戻す(移行計画 M7)。

**更新(M7b、2026-10-10): プロジェクトごとの保存をやめ、全体で 1 つの `session.json` に、フレーム(macOS のウィンドウ)の並びとして保存する**([buffer-model.md](buffer-model.md) §7・§9)。下の「範囲」は、1 フレーム分のスナップショットとして、各フレームにそのまま使う。保存先・保存の動き・形式は、下の「保存先」の更新を参照。

## 範囲(合意済み: A 案)

フレームごとに、次を保存して、次の起動で復元する。

- window の分割配置(分割の向き、window の並び、分割の比率。比率は省略可で、省略は均等。`C-x ^` などやモードラインのドラッグで変えた大きさを戻す)
- 各 window の参照履歴(文書・アンカー・閲覧位置)と、履歴の現在位置
- 選択中の window
- buffer の、最近使った順(`C-x b` の候補順)
- **選択範囲**(文書内で選択していたテキスト): 表示されたテキストの中の位置(開始・終了)と、選択していた文字列を、1 件だけ保存する(長さは 4096 文字まで)。復元は、その window が、保存したときと同じ文書を表示していて、**その位置の文字列が一致するときだけ**行う(文書が書き換わっていれば、ずれた場所を選ばないよう、戻さない)。選択範囲だけが壊れていても、ほかは復元する。段落全体の選択(範囲の端が要素になる場合)も保存できる。

保存しないもの:

- **文書の内容**(復元時に、ファイルから読み直す。最新の内容が表示される)
- 仮想 buffer(`*search: …*`、`*Help: …*`): 履歴から外す。履歴の残りで、現在位置を決める
- 入力途中のミニバッファ、検索語(`C-s` の前回の語)、ウィンドウの大きさ・位置、リンクの選択(TAB)
- 信頼するルートは、別の保存先(`trusted-roots.json`)で、すでに永続化している

**A 案との差(要確認):** 合意した A 案は、各 window の現在の文書と閲覧位置まで。実装は、window の現在位置が履歴の一部なので、各 window の参照履歴(Back / Forward)も、そのまま保存・復元している(B 案相当。1 window あたり 100 件まで。多いときは、現在位置を含む範囲に切る)。履歴を復元しない(現在の文書だけ)にするなら、`core/src/session.ts` の `MAX_HISTORY` を 1 にする程度の変更で足りる。

## 設定

`config.json` の `restoreSession`(既定 `true`)。`false` のあいだは、復元も保存もしない([configuration.md](../user/configuration.md))。

プロジェクトという単位はなくなった(起動時は、前回の状態を復元する。引数のファイルは、復元した状態に開く)。

## 保存先

```
~/Library/Application Support/HyperBuf/session.json
```

- **全体で 1 つのファイル**。フレームの並び(version 2): `{"version": 2, "active": <スロット>, "frames": [{"slot": 1, "rect": {x, y, width, height}, "snapshot": {…}}]}`。`snapshot` は、Web コアが作る 1 フレーム分(上の範囲)。`rect` は、ウィンドウの位置と大きさ(復元時に、いまの画面に収まるよう補正する)。
- 置き場所は 0700、ファイルは 0600。一時ファイルに書いてから置き換える。
- 大きさは 4 MB まで(超えるものは、保存しない・読まない)。スロットは 1〜9(不正・重複したフレームは、捨てる)。
- 以前のプロジェクトごとのファイル(`sessions/<ハッシュ>.json`)は、使わない(引き継がない)。

## 保存と復元の動き

- **保存:** Web コアが、表示の更新・スクロールのたびに、1 秒待ってから(連続する変更は 1 回にまとめて)、フレームごとに保存する。ホストは、全フレームのスナップショットを集めて、さらに 0.5 秒待って、1 つのファイルに書く。内容が前回と同じなら、書かない。ページが非表示になる・ウィンドウを閉じる・アプリを終了するときは、待たずに書く(終了は、保存が終わる(最大 1.5 秒)まで待つ)。
- **復元:** 起動して、前回のフレームをすべて作り、それぞれのスナップショットを復元する。復元のあとに、保存を始める(復元の前に書いて、前回の状態を消さない)。文書が存在するかは、読んでみて分かる。
- **信頼しない入力として扱う:** Web コアが、形・型・件数・長さを厳密に検証する(`core/src/session.ts`)。壊れていれば、部分的には使わず、通常の起動にする。シェル(Swift)は、JSON として読めること、大きさだけを見る。
- **なくなった文書:** 履歴から外す(現在位置は、ひとつ前の参照になる)。window の履歴が空になれば、その window をたたむ(分割をなくす)。すべてなくなれば、通常の起動にする。
- 読めなくなった文書(権限など)も、同じ扱い。

## 決めていないこと

- ウィンドウ(macOS)の大きさ・位置は、フレームごとに保存する(`rect`)。
