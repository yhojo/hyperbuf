# セッションの復元

アプリを終了して起動し直したあとに、作業中の状態を戻す(移行計画 M7)。

## 範囲(合意済み: A 案)

プロジェクトごとに、次を保存して、そのプロジェクトを開いたときに復元する。

- window の分割配置(分割の向き、window の並び)
- 各 window の参照履歴(文書・アンカー・閲覧位置)と、履歴の現在位置
- 選択中の window
- buffer の、最近使った順(`C-x b` の候補順)

保存しないもの:

- **文書の内容**(復元時に、ファイルから読み直す。最新の内容が表示される)
- 仮想 buffer(`*search: …*`、`*Help: …*`): 履歴から外す。履歴の残りで、現在位置を決める
- 入力途中のミニバッファ、検索語(`C-s` の前回の語)、ウィンドウの大きさ・位置
- 信頼するルートは、別の保存先(`trusted-roots.json`)で、すでに永続化している

**A 案との差(要確認):** 合意した A 案は、各 window の現在の文書と閲覧位置まで。実装は、window の現在位置が履歴の一部なので、各 window の参照履歴(Back / Forward)も、そのまま保存・復元している(B 案相当。1 window あたり 100 件まで。多いときは、現在位置を含む範囲に切る)。履歴を復元しない(現在の文書だけ)にするなら、`core/src/session.ts` の `MAX_HISTORY` を 1 にする程度の変更で足りる。

## 設定

`config.json` の `restoreSession`(既定 `true`)。`false` のあいだは、復元も保存もしない([configuration.md](configuration.md))。

起動時にどのプロジェクトを開くか(前回のプロジェクトを自動で開くか、など)は、このセッションの復元とは別の問題で、**プロジェクトの扱いとして別途検討する**(未決定)。

## 保存先

```
~/Library/Application Support/HyperBuf/sessions/<プロジェクトのルートの SHA-256>.json
```

- プロジェクトのルート(`realpath` で正規化)ごとに 1 ファイル。ファイルには、ルートのパスも入れ、一致しなければ使わない。
- 置き場所は 0700、ファイルは 0600。一時ファイルに書いてから置き換える。
- 大きさは 1 MB まで(超えるものは、保存しない・読まない)。

## 保存と復元の動き

- **保存:** 表示の更新・スクロールのたびに、1 秒待ってから(連続する変更は 1 回にまとめて)書く。内容が前回と同じなら、書かない。ページが非表示になる・ウィンドウを閉じる・アプリを終了するときは、待たずに書く(終了は、保存が終わる(最大 1.5 秒)まで待つ)。
- **復元:** 起動して、ファイル一覧を取ったあとに、保存を読む。復元のあとに、保存を始める(復元の前に書いて、前回の状態を消さない)。
- **信頼しない入力として扱う:** Web コアが、形・型・件数・長さを厳密に検証する(`core/src/session.ts`)。壊れていれば、部分的には使わず、通常の起動にする。シェル(Swift)は、JSON として読めること、大きさだけを見る。
- **なくなった文書:** 履歴から外す(現在位置は、ひとつ前の参照になる)。window の履歴が空になれば、その window をたたむ(分割をなくす)。すべてなくなれば、通常の起動にする。
- 読めなくなった文書(権限など)も、同じ扱い。

## 決めていないこと

- 起動時に開くプロジェクトの選び方(プロジェクトの扱いとして、別途)。
- 複数のウィンドウ(プロジェクト)を同時に開く場合の保存。
- ウィンドウの大きさ・位置、分割の比率(現在は、均等分割のみ)。
