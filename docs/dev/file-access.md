# ファイルのアクセス判定

HyperBuf が、どのファイルを確認なしで開き、どのファイルを確認してから開くかの規則。バッファの概念は [buffer-model.md](buffer-model.md)、設定キーの一覧は [configuration.md](../user/configuration.md)、外部連携(ソケット・URL スキーム)の契約は [integration-protocol.md](integration-protocol.md)。

## 1. 方針

HyperBuf は、ビューアとして**任意の場所の Markdown を読める**。一方で、Markdown は信頼できない入力(AI エージェントが書いたものを含む)なので、**リンクや外部からの要求によって、利用者が意図しないファイルが読まれない**ようにする。

- 「プロジェクトの内か外か」ではなく、**パスの規則**で決める。設定に書く**警告パス**の下にあるファイルだけを、開く前に確認する。
- **利用者が自分で選んだパスは、判定しない。** `C-x C-f` や `C-x p f` で打った(選んだ)パスは、利用者の意思そのもの。
- 判定は Swift 側(`FileAccess`)が行う。Web コアは、確認の表示だけを担当し、判断を信用されない(§5 の最終確認を参照)。

## 2. 判定の対象と経路

次の経路は、すべて同じ判定を通る。

- リンクのクリック
- CLI・Emacs・URL スキームからの「開く」
- 文書が参照する画像などのリソース

経路によって、判定の厳しさが違う。URL スキーム(`hyperbuf://open?...`)は、ブラウザ上の任意のページなど、**起点を特定できない**経路から起動できる。パスの規則だけで判定せず、起点で扱いを分ける。

| 経路                                               | 判定                                                                   |
| -------------------------------------------------- | ---------------------------------------------------------------------- |
| ソケット(CLI、Emacs。CLI の初回起動を含む。下の注) | 同一ユーザーのプロセスなので、パスの規則(§3)だけで判定する             |
| **URL スキーム**                                   | 許可パスにないファイルは、**警告パスの外でも、ミニバッファで確認する** |
| リンクのクリック、リソース                         | パスの規則(§3)だけで判定する                                           |
| `C-x C-f`、ミニバッファで打ったパス                | 判定しない(利用者の意思)                                               |

**注: CLI の初回起動。** CLI は、アプリが起動していないとき、`hyperbuf://ping`(起動だけ)でアプリを起動し、ソケットが現れるまで待ってから、ソケットで「開く」要求を送る。CLI と Emacs の要求は、すべてソケットを通る。URL スキームは、アプリの起動と、外部リンクからの「開く」に使う。最初のファイルを URL で渡して起動する方式にすると、起動のたびに URL スキームの確認が出てしまうため、この形にしている。

確認は、**行き先のフレーム**のミニバッファに出る(外部からの「開く」の行き先は、最後にアクティブだったフレーム。[buffer-model.md](buffer-model.md) §7)。

## 3. パスの規則

パスを正規化(`realpath`。シンボリックリンクは実体で判定する)したうえで、設定の**許可パス**と**警告パス**を照合する。

1. どちらにも一致しなければ → **開く**。
2. 一致するものがあれば、**一番長く一致したもの**が勝つ(より具体的な指定が優先)。
   - 許可パスが勝つ → 開く。
   - 警告パスが勝つ → ミニバッファで確認する。
3. 許可と警告が**同じパス**で重なっていれば、安全側の警告にして、設定の問題として報告する。

| 設定                                             | ファイル               | 結果                   |
| ------------------------------------------------ | ---------------------- | ---------------------- |
| `allowPaths: ~/work`、`warnPaths: ~/work/vendor` | `~/work/vendor/x.md`   | 警告(具体的な方が勝つ) |
| `allowPaths: /usr/share/doc`、`warnPaths: /usr`  | `/usr/share/doc/a.md`  | 許可                   |
| (どちらにも一致しない)                           | `~/Downloads/foo/a.md` | 開く                   |

- パスの一致は、区切りの境界で判定する(`/tmp` が `/tmp2` に一致しない)。存在しないパスの比較は、大文字小文字を区別しない(APFS)。
- `allowPaths` は、警告パスと重なる場所でだけ意味を持つ(警告パスの下で、確認を省く場所を指定する)。

## 4. 確認と記憶

- 警告パスのファイルを開くときは、ミニバッファで確認する。
- 承認すると、そのファイルのディレクトリ以下を記憶し、次からは確認しない。記憶は永続化され、実質は具体的な許可パスとして働く。
- **記憶の範囲の制限:** 記憶するディレクトリが、**警告パスそのもの、またはその上位**になる場合は、ディレクトリではなく、**そのファイル単体**だけを記憶する(`/tmp/x.md` を承認して、`/tmp` 全体が許可になるのを防ぐ)。
- まとめて許可したい場所は、`allowPaths` に書く。
- 記憶したパスの**一覧と取り消し**は、`M-x forget-remembered-path` で行う(記憶したパスが候補に出て、`RET` で選んだものを取り消す)。
- 記憶の保存先は、利用者が書く `config.json` とは別(`trusted-roots.json`)。**アプリは設定ファイルを書き換えない。**
- 記憶と設定は、全フレームで共有する(ホスト側で管理する)。

## 5. 画像などのリソース

リソースは、文書の描画中に非同期で読み込まれるので、その場で確認を出して止められない。次の流れにする。

1. 描画の**前**に、文書内のローカル画像のパスを集めて、まとめてホストに判定させる。
2. 警告対象のリソースは、読み込まずに、プレースホルダーを出す。
3. 描画のあとに、「警告対象のパスの画像が N 件あります(`<ディレクトリ>`)。許可しますか?」とミニバッファで一度だけ聞く。
4. 確認を出すのは、**アクティブなフレームの選択中の window の文書だけ**(セッションの復元で、複数のフレームが同時に確認を出さないため)。それ以外の文書は、プレースホルダーのまま待ち、その window が選択されたときに聞く。
5. 承認したら、そのディレクトリを記憶し、描画し直す。断った場合は、**そのセッションの間は覚えて**、ファイルの更新による再描画で聞き直さない。
6. 許可・拒否の**最終判定は、スキームハンドラ側で必ず再確認する**(Web コアの判断を信用しない)。

## 6. 既定値

- `warnPaths` の既定: `/usr`、`/opt`、`/tmp`、`/var`、`/etc`、`/System`、`/Library`、および、ホスト配下の機微な場所 `~/.ssh`、`~/.aws`、`~/.gnupg`、`~/Library`。
- `allowPaths` の既定: `~/Library/Mobile Documents`(iCloud Drive。`~/Library` の警告より、長い一致が勝つ)。
- `/Volumes`(外付けドライブ)は、警告に入れない。自分の文書を毎回確認されないようにするためで、代わりに、再帰の列挙のタイムアウト([buffer-model.md](buffer-model.md) §6.1)で守る。
- macOS では `/tmp`、`/var`、`/etc` が `/private/...` へのシンボリックリンクなので、設定のパスも、読み込み時に正規化して照合する。存在しないパスは、文字列のまま使う。

## 7. 設定

```json
{
  "warnPaths": ["/usr", "/opt", "/tmp", "/var", "/etc", "/System", "/Library"],
  "allowPaths": ["~/work", "/usr/share/doc"]
}
```

- `warnPaths` は、書いたら既定の一覧を**置き換える**。`[]` で警告なし。`allowPaths` も同じ。
- `~` は展開する。絶対パスでないもの、型が違うものは、無視して理由を `C-h b` の「設定の問題」に出す。
- キーの一覧は [configuration.md](../user/configuration.md)。
