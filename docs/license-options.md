# HyperBuf 自体のライセンスの選択肢

状態: **決定(2026-10-10)**。

- **HyperBuf 本体: Apache-2.0。** 著作権者の表記は `Copyright 2026 Yasuo Hojo`。
- **`emacs/`: GPL-3.0-or-later**(ディレクトリごとにライセンスを分ける。当面はモノレポのまま。ELPA に載せるときは、履歴を保って切り出せる)。
- **`elkjs`: バンドルから外した**(下の「推奨」の 3)。
- 反映: ルートの `LICENSE`(Apache-2.0)と `NOTICE`、`emacs/LICENSE`(GPL-3.0)、各ソースファイルの SPDX 表記(`scripts/check-license-headers.sh` が検査)、`core/package.json`、アプリの `Info.plist` の著作権表記、アプリに同梱する `LICENSE.txt` / `NOTICE.txt` / `THIRD-PARTY-NOTICES.txt`、README。

以下は、決めるまでの検討の記録。

## 前提(洗い出した事実)

[third-party-licenses.md](third-party-licenses.md) のとおり、同梱するサードパーティのソフトウェアは、ほぼすべて**許容的なライセンス**(MIT、ISC、BSD、Apache-2.0)で、**GPL 系はない**。例外は次の 2 つ。

| 対象                                                                | ライセンス                          | 影響                                                                                                         |
| ------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `elkjs`(Mermaid の ELK レイアウト用。遅延ロードのチャンク約 1.5 MB) | EPL-2.0(弱いコピーレフト)           | **バンドルから外した**(下の「推奨」の 3)。同梱するなら、ソースの入手先を示す必要があり、GPL とは結合できない |
| starry-night の文法のうち MPL-2.0 のもの                            | MPL-2.0(ファイル単位のコピーレフト) | 改変しないので、著作権表示とライセンス文を含めれば足りる。GPL とも結合できる                                 |

- Swift 側(アプリ・CLI・プロトコル)と Emacs 連携は、サードパーティの依存を持たない(すべて自作)。
- リポジトリのコミットの作者は、1 名(Yasuo Hojo)。著作権者の表記の決定が要る。

## 選択肢の比較

|                                                           | MIT                | Apache-2.0                                     | MPL-2.0                      | GPL-3.0                |
| --------------------------------------------------------- | ------------------ | ---------------------------------------------- | ---------------------------- | ---------------------- |
| 種類                                                      | 許容的             | 許容的 + 特許の明示的な許諾                    | ファイル単位のコピーレフト   | 強いコピーレフト       |
| 閉じた派生物(改変して、ソースを出さずに配る)              | 可                 | 可                                             | 改変したファイルは公開が要る | 不可                   |
| 特許                                                      | 言及なし           | 貢献者の特許を明示的に許諾(訴訟を起こすと失効) | 同様に許諾                   | 同様に許諾             |
| 商標                                                      | 言及なし           | 商標は許諾しない(明記)                         | 同様                         | 言及なし               |
| 同梱物(MIT / Apache / BSD)との相性                        | ○                  | ○                                              | ○                            | ○                      |
| 同梱物 `elkjs`(EPL-2.0)との相性(外したので、今は問題なし) | ○                  | ○                                              | ○                            | **×**                  |
| 条件の長さ                                                | 短い               | 長い(NOTICE の扱いなど)                        | 中                           | 長い                   |
| Emacs 連携(`emacs/`)との関係                              | 可(GPL と両立する) | 可(GPLv3 と両立する)                           | 可                           | 自然(Emacs 本体と同じ) |

## Emacs 連携(`emacs/`)の扱い

- Emacs の Lisp のパッケージは、Emacs(GPL)と強く結びつくため、GPL と**両立するライセンス**で出すのが慣例。MIT、Apache-2.0(GPLv3 と両立)、MPL-2.0 は、いずれも GPL と両立する。
- **GNU ELPA** に載せたい場合は、GPL-3.0-or-later と、著作権の FSF への譲渡が条件になる(NonGNU ELPA や MELPA は、GPL と両立するライセンスなら可)。
- モノレポでも、ディレクトリごとにライセンスを分けられる(`emacs/` だけ GPL-3.0-or-later、など)。

## 推奨

1. **アプリ・Web コア・CLI・プロトコル: Apache-2.0。**
   - 許容的で、閲覧ツールとして広く使われやすい。特許の許諾が明示され、商標を許諾しない旨が明記される(「HyperBuf」の名前を守りやすい)。同梱物の大半が MIT / Apache-2.0 / ISC / BSD なので、足並みがそろう。
   - 手軽さを優先するなら、MIT でもよい(条件が短い。特許・商標への言及はない)。
2. **`emacs/`: GPL-3.0-or-later**(任意)。Emacs の流儀と、ELPA への道を残す。単純さを優先するなら、全体を同じライセンスにする。
3. **`elkjs`: バンドルから外した**(決定、2026-10-10)。
   - **訂正:** 当初は「ELK は `layout: elk` を指定したときだけ使う」と説明したが、**間違いだった**。同梱の Mermaid 12.1 は、既定の設定が `layout: "elk"` で、フローチャート・クラス図・状態遷移図などが、何も指定しなくても ELK で描画される。
   - そこで、**既定のレイアウトを dagre に固定**した(`core/src/ui/diagrams.ts`)。dagre は Mermaid 11 までの既定で、GitHub の表示と同じ。`elkjs` は、空の実装(`core/src/stubs/elkjs-disabled.js`)に差し替えて同梱しない(`core/build-options.mjs`)。
   - 図が `layout: elk` を明示すると、その図だけが、図の位置にエラーとして表示される(文書全体は止まらない)。`dist` は約 3.6 MB 減った。
   - これで、EPL-2.0 の条件(ソースの入手先の表示)が不要になり、将来 GPL を選ぶ余地も残る。

コピーレフト(GPL-3.0)を選ぶ理由があるとすれば、「改変版を、ソースを出さずに配られたくない」場合。`elkjs` は外したので、GPL-3.0 も選べる。

## 決めること

1. 許容的(Apache-2.0 / MIT)か、コピーレフト(MPL-2.0 / GPL-3.0)か。
2. `emacs/` を別のライセンスにするか、同じにするか。
3. 著作権者の表記: `Copyright 2026 Yasuo Hojo`(決定)。
4. 決まったら: `LICENSE` ファイル、各ファイルのヘッダ(SPDX の 1 行)、アプリの About と同梱ファイル、README に反映する。
